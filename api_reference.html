闹钟 Agent 开放 API · 接口参考与示例

把「自然语言」解析成「结构化闹钟时间」，并可托管、管理多租户闹钟。规则引擎优先（零成本），长尾由 LLM 兜底。

Base URL https://your-domain.example.com（本地：http://localhost:8080）
协议版本 v1 · 1.0.0   鉴权 Authorization: Bearer <API_KEY>

快速拿到 Key： 本地启动 node server.js 首次会自动生成一枚示例 Key（看日志）；正式 Key 用 node manage_keys.js create --label "我的应用" --rate 100 --plan pro 生成，存于 data/alarm.db（SQLite）。 更推荐直接打开 开发者门户 /portal 自助管理。

0. 通用约定

  • 鉴权：所有 /v1/* 接口（除 /v1/health）都需 Authorization: Bearer <API_KEY>。缺失→401 missing_api_key，无效→401 invalid_api_key，禁用→403 key_disabled。
  • 限流：按 Key 的 60 秒滑动窗口，默认 60 次/分（每 Key 可覆盖）。超额→429 rate_limited，带 Retry-After 头。
  • 统一错误体：{ "error": { "code": "...", "message": "..." }, "request_id": "req_..." }
  • HTTP 200 ≠ 解析成功：模糊输入返回 200 但 success:false + clarification，由调用方决定是否追问。
  • 时区：固定 Asia/Shanghai（UTC+8，无夏令时），除非显式覆盖。

3. 托管闹钟 CRUD（多租户隔离）

闹钟按 API Key 的 tenant 自动隔离，调用方无感知。无需自建存储，平台托管。以下以 <KEY> 代表你的 Key。

3.1 创建（自然语言）

POST/v1/alarms
请求（带幂等键）
curl -X POST https://your-domain.example.com/v1/alarms \
  -H "Authorization: Bearer <KEY>" \
  -H "Content-Type: application/json" \
  -d '{"text":"明天早上8点叫我起床","idempotency_key":"order-9981"}'
响应 201（新建） / 200（幂等命中，重复提交返回已有记录）
{
  "id": "a_1f3c9a2b7d8e4f60",
  "tenant": "demo",
  "text": "明天早上8点叫我起床",
  "alarm": { "timestamp": 1760563200, "datetime": "2026-10-10T08:00:00+08:00",
             "date": "2026-10-10", "time": "08:00", "recurrence": "none",
             "timezone": "Asia/Shanghai", "lead_minutes": 0, "label": "起床", "enabled": true },
  "enabled": true,
  "created_at": "2026-10-09T17:00:00.000Z",
  "updated_at": "2026-10-09T17:00:00.000Z",
  "idempotency_key": "order-9981",
  "next_trigger": 1760563200000,
  "request_id": "req_01HX...",
  "idempotent": false
}
支持两种创建：① 传 text 由平台解析；② 传 time + 可选 date/recurrence/timezone/label 显式创建。模糊输入（解析不出时间）→ 422 + clarification。

3.3 获取 / 更新 / 删除单条

GET/v1/alarms/:id PATCH/v1/alarms/:id DELETE/v1/alarms/:id
获取
curl https://your-domain.example.com/v1/alarms/a_1f3c9a2b7d8e4f60 \
  -H "Authorization: Bearer <KEY>"
更新（禁用 / 或改自然语言重解析）
curl -X PATCH https://your-domain.example.com/v1/alarms/a_1f3c9a2b7d8e4f60 \
  -H "Authorization: Bearer <KEY>" -H "Content-Type: application/json" \
  -d '{"enabled":false}'           # 或 {"text":"后天上午10点吃药"} 重新解析
删除
curl -X DELETE https://your-domain.example.com/v1/alarms/a_1f3c9a2b7d8e4f60 \
  -H "Authorization: Bearer <KEY>"
# → { "ok": true, "id": "a_1f3c9a2b7d8e4f60", "request_id": "req_01HX..." }
PATCH 可局部更新 text / recurrence / time / date / label / timezone / lead_minutes / enabled，服务端自动重算 next_trigger。不存在或不属于当前租户→ 404。

4. Webhook 触发投递 & 用量计量（Phase 3）

托管闹钟到点后，平台会向租户配置的回调 URL 推送 alarm.fired 事件（带 HMAC 签名 + 3 次指数退避重试），由你决定发推送 / SMS / 触发业务。同时提供按 Key 的调用与触发用量统计，为计费打地基。

4.1 配置回调地址

GET/v1/webhook POST/v1/webhook
设置（须 https；本地联调用 http://localhost 允许）
curl -X POST https://your-domain.example.com/v1/webhook \
  -H "Authorization: Bearer <KEY>" -H "Content-Type: application/json" \
  -d '{"url":"https://example.com/alarm-hook"}'
# → {"ok":true,"url":"https://example.com/alarm-hook","verified":true,"request_id":"req_..."}
# 传 url:"" 清空配置
查询
curl https://your-domain.example.com/v1/webhook -H "Authorization: Bearer <KEY>"
# → {"url":"https://example.com/alarm-hook","verified":true,"request_id":"req_..."}

4.2 接收端：如何验证与处理

服务端投递的请求头与事件体示例：

POST https://example.com/alarm-hook
Headers:
  Content-Type: application/json
  X-Alarm-Event: alarm.fired
  X-Alarm-Delivery-Id: <每次投递唯一，用于去重>
  X-Alarm-Signature: sha256=<HMAC-SHA256(body, API_KEY)>

Body:
{
  "event": "alarm.fired",
  "alarm_id": "a_1f3c9a2b7d8e4f60",
  "tenant": "demo",
  "text": "明天早上8点叫我起床",
  "alarm": { "timestamp": 1760563200, "time": "08:00", "recurrence": "none",
             "timezone": "Asia/Shanghai", "label": "起床", "enabled": true },
  "fired_at": "2026-10-10T00:00:00.000Z",
  "request_id": "req_01HX..."
}
验签（Node 示例）
const crypto = require('crypto');
function verify(rawBody, signatureHeader, apiKey){
  const expected = 'sha256=' + crypto.createHmac('sha256', apiKey)
                      .update(rawBody).digest('hex');
  return crypto.timingSafeEqual(Buffer.from(expected), Buffer.from(signatureHeader));
}
投递失败（非 2xx）会按 1s / 2s / 4s 退避重试共 3 次；仍失败则记入日志（不阻塞调度）。建议在接收端用 X-Alarm-Delivery-Id 做幂等。

GET/v1/usage

4.4 密钥自助管理（开发者门户同款接口）

密钥按租户隔离，只能查看/管理自己租户的密钥。创建密钥时可指定套餐（free/pro/enterprise），决定默认限额与月度解析配额。

GET/v1/keys POST/v1/keys POST/v1/keys/:key/disable|enable
创建专业版密钥
curl -X POST https://your-domain.example.com/v1/keys \
  -H "Authorization: Bearer <KEY>" -H "Content-Type: application/json" \
  -d '{"label":"生产环境","plan":"pro"}'
# → 201：返回完整 key（仅此刻返回一次，请保存）
#   {"key":"sk_live_...","tenant":"demo","label":"生产环境",
#    "enabled":true,"rate_limit":600,"plan":"pro","created_at":"...","request_id":"..."}
列出本租户密钥（Key 已脱敏）
curl https://your-domain.example.com/v1/keys -H "Authorization: Bearer <KEY>"
# → {"count":2,"keys":[{"key":"sk_live_abc1…2345","tenant":"demo",
#    "label":"生产环境","enabled":true,"rate_limit":600,"plan":"pro","created_at":"..."}],
#    "request_id":"..."}
禁用 / 启用
curl -X POST https://your-domain.example.com/v1/keys/<完整KEY>/disable \
  -H "Authorization: Bearer <KEY>"
# → {"ok":true,"key":"sk_live_...","enabled":false,"request_id":"..."}
套餐与配额：free=60 次/分 & 5k 解析/月；pro=600/分 & 100k/月；enterprise=6000/分 & 不限。/v1/parse 超出月度配额返回 402。

6. 开发者门户（Web 控制台）

平台附带开箱即用的开发者控制台，地址：/portal（与本 API 同源）。功能：

  • 密钥管理：可视化列出/创建/启用/禁用 Key（创建时选套餐）。
  • Webhook 配置：填写回调 URL，一键保存并连通性校验。
  • 用量看板：实时展示套餐、剩余配额与各指标条形图（解析/创建/更新/删除/触发）。
门户只是 /v1/* 接口的可视化封装，所有能力均以 API 形式对外开放，便于你嵌入自己的后台。

7. 错误码

HTTPcode含义
400bad_request参数错误（缺 text / 超 200 字 / 闹钟缺时间字段 / webhook_url 非法或协议不符）
401missing_api_key / invalid_api_key缺头或 Key 无效
403key_disabledKey 已禁用
402quota_exceeded本月解析配额（按套餐）已用尽，需升级或等下个计费周期
404not_found接口不存在 / 闹钟不存在或不属于当前租户 / 密钥不属于当前租户
405method_not_allowed方法不被允许
422（解析类）自然语言无法确定时间，需澄清
429rate_limited限流，含 Retry-After
500internal服务端异常
